# 질문 뎁스 가이드 네비게이션과 CMS 통합 (2026-06-08)

교수자가 무엇을 물어야 할지 모를 때를 위해, 첫 화면에서 큰 주제를 고르고 하위 항목으로 좁혀 답을 받는 3뎁스 가이드 네비게이션을 붙였다. 동시에 CMS 매뉴얼을 새로 색인하되 LMS 질문에 섞이지 않게 검색을 매뉴얼 단위로 갈랐다. 추천 질문이 엉뚱하게 답하던 문제, 배포 과정에서 코드와 데이터가 따로 놀던 문제도 함께 잡았다.

## 무엇을 했나

- **가이드 3뎁스 네비게이션.** 노션 매뉴얼의 목차를 읽어 대분류 → 하위 문서 → 답변으로 좁힌다. 목차를 코드에 박지 않아, 매뉴얼이 바뀌면 다시 색인만 하면 따라온다.
- **CMS 매뉴얼 통합과 격리.** CMS 매뉴얼을 색인에 넣되, 청크마다 소속 매뉴얼(LMS·CMS)을 표시하고 검색을 그 단위로 거른다. LMS 질문의 후보에 CMS 문서가 아예 못 들어온다.
- **FAQ 답변 원문 직출력.** 추천 질문 같은 FAQ 문서는 사람이 써 둔 정답을 모델로 다시 쓰지 않고 그대로 내보낸다.
- **문의 안내 정리.** 답변에 Q&A 게시판 링크를 걸고, 전화번호를 뺐다.
- **배포.** 이미지를 다시 빌드하고, 맥미니 데이터 동기화 절차를 정리했다. 버전 두 갈래를 브랜치로 보존했다.

## 도중에 부딪힌 문제와 해결

### 1. 추천 질문이 전부 "확인되지 않는 질문"으로 떨어졌다

검색을 매뉴얼 단위로 거르는 코드를 색인보다 먼저 넣은 것이 화근이었다. 자동 새로고침이 켜진 서버가 바뀐 코드를 바로 물었는데, 색인에는 아직 매뉴얼 표시가 없었다. 그래서 "LMS 청크만 보여 달라"는 조건이 한 건도 못 맞히고 모든 검색이 빈 결과가 됐다. 빈 결과는 곧 폴백이라, 멀쩡한 추천 질문까지 "확인되지 않는 질문"으로 떨어졌다.

색인을 다시 만들어 모든 청크에 매뉴얼 표시를 박으니 풀렸다. 배운 점은 분명하다. **검색 조건을 바꾸는 코드와 색인 스키마는 한 묶음이다.** 코드가 먼저 들어가면 데이터가 따라오기 전까지 전부 막힌다.

### 2. CMS 목차가 LMS와 반대 구조여서 파서가 0개를 냈다

CMS 목차를 파서에 넣으니 카테고리가 0개로 나왔다. 두 매뉴얼의 목차 관례가 정반대였다. LMS 목차는 `##` 제목이 대분류이고 볼드 줄은 무시할 메타 구역의 표시인데, CMS 목차는 거꾸로 볼드 줄이 대분류이고 `##`은 아예 없다. LMS만 가정한 파서가 CMS에서 헛돈 것이다.

목차에 `##`이 있으면 LMS식으로, 없으면 볼드식으로 갈라 읽도록 파서를 두 갈래로 나눴다. 같은 노션에서 내려받아도 매뉴얼마다 목차 관례가 다르다는 점을, 한 포맷을 가정하지 말아야 한다는 점을 확인했다.

### 3. 추천 질문을 눌렀더니 맥락 없는 답이 나왔다

"블루프린트를 동기화했는데 안 돼요"라는 추천 질문에 "삭제한 주차나 콘텐츠를 복원합니다"라는 한 줄만 나왔다. 원인 설명이 빠져 앞뒤가 끊겨 보였다.

검색은 정답 문서를 정확히 맞혔다. 문제는 생성이었다. gemma:4b가 사람이 써 둔 FAQ 정답("연결된 주차를 삭제하면 동기화가 안 되니, 삭제한 주차나 콘텐츠를 복원하라")을 다시 쓰면서 질문을 되풀이하고 원인을 통째로 버렸다. 사용자가 "간결하게 줄이라는 지시가 어디 있냐"고 물어 코드를 전수로 뒤졌는데, 그런 지시도 출력 길이 제한도 없었다. 모델이 스스로 줄인 것이다.

FAQ 문서는 사람이 쓴 정답이 이미 완성형이라, 모델을 거치지 않고 원문을 그대로 내보내게 했다. 가이드 문서는 길어서 종전대로 모델이 쓴다. **작은 모델로 잘 쓰인 짧은 답을 다시 쓰면 손해다. 정답이 있으면 모델을 빼는 편이 낫다.**

### 4. 맥미니에 배포했더니 추천 질문이 안 떴다

추천 질문(`/faq`)과 가이드 네비(`/catalog`)는 실행 중에 원본 데이터 폴더(`data/raw`)를 읽는다. 추천 질문은 거기서 FAQ 목록 파일을, 네비는 매뉴얼 목차 파일을 읽는다. 그런데 내가 동기화 절차에서 색인만 보내고 원본은 빼라고 안내했고, 배포 번들에도 원본이 없었다. 색인은 있는데 원본이 없으니 둘 다 빈 결과가 됐다.

원본을 포함한 번들로 다시 안내했다. 색인·원본·자산을 한 번들로 묶어 보내고, 받는 쪽은 풀고 재시작만 하면 된다. 이건 내 안내 실수였다. **무엇이 실행 중에 어떤 파일을 읽는지 정확히 알아야 한다.** 색인만 데이터라고 여긴 것이 화근이었다.

### 5. "main이 추천 질문 도입 전"이라는 가정이 틀렸다

버전을 두 갈래로 가르려는데, 사용자도 나도 main을 "추천 질문 도입 전"으로 알고 있었다. 확인해 보니 원격 main은 이미 추천 질문을 머지한 상태였다(PR #4). 가정대로 갈랐으면 엉뚱한 시점을 "이전 버전"으로 박을 뻔했다.

세 시점(진짜 도입 전 / 직전 배포본 / 오늘 작업)을 표로 정리해 사용자와 기준을 맞췄다. 그 뒤 '질문뎁스 전'(`release/not-question-depth`)과 '오늘 작업'(`release/question-depth`) 두 브랜치로 갈라 푸시했다. **브랜치를 가르기 전에 원격 상태부터 확인할 것.** 기억과 실제는 다를 수 있다.

## 배포 구조에서 짚은 것

이미지에는 코드만 들어가고, 데이터(원본·색인·자산)는 호스트 볼륨에 따로 둔다. 둘이 어긋나면 이번처럼 깨진다. 저장소가 공개라, 매뉴얼을 이미지에 함께 굽는 방법은 접었다. 데이터는 앞으로도 계속 바뀐다. 그래서 담당 선생님이 노션을 고치면 스케줄이 그 변경을 받아 호스트에서 다시 색인하는 방식으로 일관성을 맞추기로 방향을 잡았다(본 구현은 보류). 원본이 진실의 원천이고, 색인은 그때그때 코드로 다시 만든다.

## 확인한 결과

- 단위 테스트 120개 통과.
- 색인: LMS 469 + CMS 50 = 519청크, 모든 청크에 매뉴얼 표시.
- 실사용: 막혔던 추천 질문이 이미지·출처까지 정상 답변. CMS 네비 클릭과 직접 언급은 CMS로, LMS 질문은 LMS로만 닿아 섞임이 없음.
- 폴백 안내에서 전화번호가 빠지고 Q&A 게시판 링크만 남음.

## 바뀐 곳

- 가이드 네비: `generation/catalog.py`(목차 파서), `backend.py`(`/catalog`), `static/index.html`(네비 UI·Q&A 링크)
- 매뉴얼 격리: `app_types.py`, `ingest/pipeline.py`, `index/vector_store.py`, `index/bm25.py`, `retrieval/search.py`, `generation/stream.py`
- 답변 품질: `generation/stream.py`(FAQ 직출력), `generation/persona.py`·`config.py`(전화번호 제거)

## 한 줄 정리

오늘의 사고는 대부분 "코드와 데이터가 따로 움직인다"는 한 뿌리에서 나왔다. 검색 조건·색인·원본·이미지가 한 묶음으로 움직이게 맞추고, 정답이 있으면 모델을 빼니, 추천 질문이 다시 제대로 답한다.
