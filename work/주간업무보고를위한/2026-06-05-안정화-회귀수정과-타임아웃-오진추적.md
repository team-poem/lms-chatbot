# LMS 챗봇 안정화 작업 보고 (2026-06-05)

게이트 강화 이후 FAQ 응답이 깨지지 않았는지 다시 측정했다. 그 과정에서 숨어 있던 회귀 1건을 고쳤고, "생성 타임아웃"으로 보고됐던 실패를 끝까지 추적해 제품이 아니라 측정 도구의 결함임을 밝히고 고쳤다.

## 왜 했나

최근 라우팅 게이트를 여러 번 손봤다. 인사·범위 안내, 포괄 주제 폴백, 로그인 토픽을 차례로 넣었다. 이 게이트들은 모두 문서 검색 전에 동작한다. 그래서 정식 FAQ가 검색에 닿기 전에 가로채여 엉뚱한 정형 응답으로 새어 나갈 위험이 있었다. 마지막 전수 측정은 6월 1일이라 변경 이후 상태를 확인하지 못한 상태였다.

## 1. FAQ 80문항 회귀 재측정

두 단계로 확인했다.

먼저 생성 없이 빠르게 검사했다. 80개 FAQ 문장을 실제 라우팅 술어에 그대로 통과시켜, 검색 전 게이트가 가로채는 문항이 있는지 봤다. 1건이 걸렸다.

- 문항: "토론 생성 시 스레드로 답변 허용 옵션은 어떤 기능인가요?"
- 원인: `is_help_request`의 "(무슨|어떤) 기능" 패턴이 너무 넓었다. 특정 기능의 정체를 묻는 질문까지 "어떤 기능이 있냐"는 역량 문의로 오인했다.
- 수정: "어떤 기능" 뒤에 존재·제공 신호(있·제공·지원·가능)를 요구하도록 좁혔다. 테스트를 먼저 실패시키고 고쳤다.
- 결과: 다시 검사하니 80문항 모두 검색 경로로 정상 진입했다.

다음으로 검색과 생성까지 포함해 실제로 돌렸다. 캡처된 79건이 모두 문서 기반 직접 답변이었다. 과잉 거절도, 주제 안내로 빠진 것도 없었다. 고친 FAQ도 정상 답변을 냈다.

## 2. "생성 타임아웃" 오진 추적

80문항 실측에서 faq-33만 실패했다. 처음에는 로컬 모델이 느려 제한시간(180초)을 넘긴 것으로 봤다. 측정해 보니 아니었다.

| 측정 | 결과 | 해석 |
| --- | --- | --- |
| Ollama 직접 생성 | 7.2초 (38토큰) | 모델은 느리지 않다 |
| 서버 /chat 직접 호출 | 15.5초에 완결 | 서버는 정상이다 |
| 서버 로그 | /chat 81건 모두 200, 오류 0 | 서버는 멈추지 않았다 |
| 단독 재현 | 매번 197초 실패 | 일시적 현상이 아니다 |

서버는 빠르게 답했는데 브라우저 측 측정만 180초를 기다렸다. 원인은 공백이었다.

faq-33은 80문항 중 유일하게 질문에 공백이 두 칸이다("않는데  어떻게"). 브라우저는 화면에 그릴 때 연속 공백을 한 칸으로 합친다. 그런데 측정 도구는 제출한 질문 문장을 화면 텍스트와 글자까지 똑같이 대조했다. 두 칸과 한 칸이 어긋나 "질문이 화면에 나타났다"를 영영 확인하지 못했고, 그대로 180초를 기다리다 실패했다. 답변을 잘라내는 부분에도 같은 문제가 있었다.

수정은 측정 도구에서 했다. 비교 직전에 연속 공백을 한 칸으로 합치고 앞뒤를 다듬어, 공백 차이로 매칭이 깨지지 않게 했다. 두 곳(대기 조건, 답변 추출)을 모두 고쳤다. faq-33은 30초에 통과했고 답변과 출처도 정상으로 잡혔다.

제품 코드는 건드리지 않았다. 챗봇은 처음부터 정상이었다.

## 결과

- 가드레일 회귀 1건 수정. 80문항 라우팅 가로채임 0건.
- 측정 도구의 공백 처리 버그 수정. faq-33 197초 실패에서 30초 통과로 회복.
- 테스트: 제품 96건, 측정 도구 49건 모두 통과.

## 남은 것

- 측정 도구 수정을 반영해 80문항을 다시 돌리면 80/80 통과가 예상된다.
- 측정 도구 저장소에는 다른 작업이 함께 있어, 이번 변경분만 따로 커밋했다.

## 한 줄 교훈

실패를 증상으로 단정하지 않고 레이어별로 측정하면, "모델이 느리다"처럼 그럴듯한 설명이 실제로는 측정 도구 버그인 경우를 가려낼 수 있다.
