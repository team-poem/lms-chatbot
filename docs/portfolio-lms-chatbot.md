# 프로젝트 상세 기술서

## 동서대학교 LearningX LMS 교수자 응대 AI 챗봇 (RAG 기반)

> 작성일: 2026-06-01 · 1인 풀스택 개발 · Phase 1 MVP

---

## 프로젝트 개요

대학 LMS(학습관리시스템) 사용법에 대한 교수자 문의를 **검색 증강 생성(RAG, Retrieval-Augmented Generation)** 파이프라인으로 자동 응대하는 교내 AI 어시스턴트. 교육혁신처 교수학습개발센터에 반복적으로 인입되던 "출석부 처리, 퀴즈 출제, 성적 반영" 등 매뉴얼 기반 단순 문의를 **근거 문서 출처와 함께** 즉시 응답하도록 설계했다.

핵심 설계 철학은 **"환각(hallucination) 차단"과 "개인정보 자기결정권 보장"**이다. 외부 LLM API를 일절 사용하지 않고 **전 과정을 온프레미스(로컬)에서 처리**하여 교내 데이터의 외부 유출 가능성을 원천 차단했으며, 가이드 문서에 근거가 없는 질문에는 추측 대신 담당 부서 안내로 폴백(fallback)하는 보수적 응답 정책을 적용했다.

- **개발 형태:** 1인 풀스택 개발 (기획·설계·구현·테스트·배포 전 주기)
- **현재 단계:** Phase 1 MVP 완성 (실 서비스 배포 준비)
- **규모:** 애플리케이션 코드 약 1,600 LOC, 162개 문서 청크 인덱싱, 단위 테스트 28건 통과

---

## 주요 기능 및 특징

### 1. 하이브리드 검색 엔진 (Hybrid Retrieval)
- 키워드 기반 **BM25**(어휘 매칭)와 **BGE-M3 임베딩 기반 벡터 검색**(의미 매칭)을 **가중 결합(BM25 0.4 : Vector 0.6)**하여, 오타·동의어에 강하면서도 정확한 용어 매칭을 동시에 달성.
- 점수 정규화(min-max) 후 결합하는 자체 랭킹 로직으로 두 이질적 점수 체계를 통합.

### 2. 환각 억제 2단 관문 (Guardrail)
- **절대 임계값**(top score 0.25)과 **1위 대비 상대 비율**(50%) 이중 필터로, 무관한 문서가 컨텍스트에 섞이는 것을 차단.
- 근거 부족 시 LLM 호출 없이 "담당 부서 문의" 메시지로 즉시 폴백 → 잘못된 답변으로 인한 업무 혼선 방지.
- 시스템/모델 정보를 캐묻는 **메타 질문 가드레일** 별도 구현 (프롬프트 인젝션·정보 유출 방어).

### 3. 실시간 스트리밍 응답 (SSE)
- Server-Sent Events로 토큰 단위 스트리밍, 체감 대기시간 단축.
- 응답과 함께 **근거 문서 출처(Notion 링크)** 및 **관련 스크린샷 이미지**(중복 제거·등장순 보존, 최대 5장)를 별도 영역에 렌더링 → 교수자가 원문을 직접 확인 가능.

### 4. 개인정보보호 준수 설계 (Privacy by Design)
- 사용 전 **동의 모달**(수집 항목·목적·6개월 보유기간·철회 방법 고지), **원클릭 동의 철회 및 대화 전량 삭제(purge)** 기능.
- SQLite `ON DELETE CASCADE`로 세션 삭제 시 연관 대화·피드백까지 물리 삭제.
- XSS 방어(입력 이스케이프), 모델 학습 미사용·제3자 미제공 명시.

### 5. 응답 품질 모니터링 루프
- 턴 단위 **피드백 수집(도움됨/안됨)**, 응답 지연시간(latency_ms)·검색 점수·출처를 로깅 → 가이드북 보강 우선순위 도출용 데이터 축적.

### 6. 자동화된 인덱싱 파이프라인
- Notion export(ZIP) 재귀 해제 → 마크다운/CSV 정제 → 청킹 → 이미지 경로 재매핑(URL 인코딩 한글 처리) → 임베딩·BM25 동시 인덱싱을 단일 CLI 명령으로 처리.

## 기술 스택

| 영역 | 기술 |
|------|------|
| **Backend** | Python 3, FastAPI, Uvicorn (ASGI), Pydantic |
| **AI / LLM** | Ollama(`gemma3:4b`, 로컬 추론), Sentence-Transformers(`BAAI/bge-m3` 임베딩) |
| **검색 / RAG** | ChromaDB(벡터 스토어), rank-bm25(키워드 검색), 자체 하이브리드 랭킹·청킹 로직 |

| **데이터** | SQLite(세션·대화·피드백, FK CASCADE), pandas(CSV 처리) |
| **DevOps** | Docker / Docker Compose, 헬스체크, 환경변수 기반 설정(dotenv), Bash 부트스트랩 |
| **품질** | pytest(28 테스트), 모듈 단위 책임 분리(ingest·index·retrieval·generation·db 계층화) |

## 1인 개발자로서 주도한 점

- **아키텍처 전 영역 설계:** 인덱싱 → 하이브리드 검색 → RAG 생성 → API → UI까지 **5개 계층을 책임 분리**하여 설계·구현. 각 계층을 독립 테스트 가능하도록 구성.
- **하이브리드 랭킹 알고리즘 직접 구현:** 라이브러리에 의존하지 않고 BM25·벡터 점수의 정규화·가중 결합·이중 임계 필터링 로직을 직접 작성.
- **온프레미스 제약 하의 의사결정:** 외부 API 금지라는 개인정보 제약을 만족시키기 위해 로컬 LLM(Ollama) + 로컬 임베딩(BGE-M3) 조합을 선정하고, Docker가 호스트 네이티브 Ollama에 접속하는 네트워크 구성까지 직접 설계.
- **프롬프트 엔지니어링:** 교수자 대상 페르소나(군더더기 없는 격식체, 마크다운 금지, 근거 외 답변 차단)를 정교하게 설계한 시스템 프롬프트 작성.
- **개인정보 컴플라이언스 자체 충족:** 동의·철회·보유기간·물리삭제까지 법적 요건을 코드로 구현.
- **테스트 주도 개발:** 전처리·청킹·BM25·하이브리드·필터·DAO·추출 등 핵심 로직에 단위 테스트 28건 작성·통과.

## 예상 정량적 성과 (추정치 — 산출 근거 포함)

> ⚠️ 아래 수치는 **합리적 가정에 기반한 추정**이며 실측 데이터가 아님. 면접 시 가정과 함께 제시하는 것을 전제로 함.

| 지표 | 추정 효과 | 산출 근거 / 가정 |
|------|-----------|------------------|
| **1건당 응답 시간** | 평균 5~10분 → **30초 내외 (약 90% 단축)** | 기존: 담당자가 매뉴얼 검색·작성·회신. 챗봇: 즉시 출처 포함 응답 |
| **반복 문의 자동 처리율** | 매뉴얼 기반 단순 문의의 **약 60~70% 자동 응대** | "출석/퀴즈/성적" 등 정형 문의가 전체의 다수라는 가정. 근거 미달 건은 담당자 이관 |
| **담당자 응대 공수** | 단순 문의 처리 시간 **주당 약 50~60% 절감** | 자동 처리율 × 1인 담당 가정. 복잡·예외 문의는 사람이 처리 |
| **응대 가용 시간** | 업무시간 한정 → **24/7 상시 응대** | 야간·주말 교수자 셀프서비스 가능 |
| **응답 일관성** | 담당자별 편차 제거, **단일 근거 기반 표준 응답** | 동일 가이드 인용으로 정보 정확성·일관성 확보 |

**면접용 방어 포인트:** "도입 전 데이터가 없어 추정치로 제시했고, 피드백 로깅·latency 측정 기능을 내장해 **배포 후 실측으로 검증할 설계**를 갖췄다"고 설명하면 오히려 데이터 기반 사고를 어필할 수 있음.

## 시스템 아키텍처 (참고)

```
[Notion Export ZIP]
        │  ingest pipeline (해제 → 정제 → 청킹 → 이미지 재매핑)
        ▼
 ┌──────────────┬──────────────┐
 │  ChromaDB    │   BM25 index  │   ← 임베딩(BGE-M3) + 키워드 동시 인덱싱
 │ (벡터 검색)  │ (어휘 검색)   │
 └──────┬───────┴───────┬──────┘
        │  hybrid_search (정규화 → 가중결합 0.4:0.6)
        ▼
   [이중 임계 필터: 절대 0.25 + 상대 50%]
        │  근거 충분
        ▼
   [persona 프롬프트 + 컨텍스트] → Ollama(gemma3:4b)
        │  SSE 토큰 스트리밍
        ▼
   [FastAPI] ──► [Vanilla JS UI]  (답변 + 출처 + 이미지 + 피드백)
        │
        ▼
   [SQLite: 세션 / 대화 / 피드백 + latency 로깅]
```
