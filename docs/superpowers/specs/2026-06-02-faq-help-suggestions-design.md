- 작성일: 2026-06-02
- 상태: 초안 → 사용자 리뷰 대기
- 목표: 역량/가이드 문의와 범위 내 주제 선언을 **하드 거절하지 않고**, 무엇을·어떻게 물어볼 수 있는지 **카테고리+예시 질문으로 안내**한다. 임베딩 게이트 강도는 그대로 유지한다.

## 1. 동기

배포된 챗봇의 실제 대화에서 과잉 거절이 재현됐다(2026-06-02 사용자 제보):

| 입력 | 실제 응답 | 문제 |
|------|-----------|------|
| "안녕하세여" | 인사말 | ✅ 정상(소셜 완화 동작) |
| "강의 운영 관련해서 문의하고싶은데여" | 거절(상담센터 연결) | ❌ 봇 인사말이 광고하는 "강의 운영"인데 거절 |
| "어떤걸 가이드 받을수잇죠?" | 거절 | ❌ 역량 문의인데 거절 |
| "아니 그래도 가이드 받을껄 보고싶은데여" | 거절 | ❌ 역량 문의인데 거절 |
| "어떤걸 도와주실수 있는데여?" | 인사말 | ⚠️ "도와"가 역량 정규식에 걸려 통과했으나 밋밋한 인사뿐 |

### 근본 원인 (체계적 디버깅으로 규명, 분류기 실측 확인)

- **RC-A — 역량/도움 질문 인식 누락**: `generation/guardrail.py`의 `_SOCIAL_CAPABILITY` 정규식이 `도와/할 수 있/도움/기능`만 잡는다. "도와주실수"엔 "도와"가 있어 통과했지만, "가이드 **받을** 수 있죠"엔 해당 키워드가 없어 게이트로 떨어져 거절. 같은 의도가 표현 한 끗 차이로 갈렸다.
- **RC-B — 범위 내 주제 선언 거절**: "강의 운영 관련 문의하고싶어요"는 *구체적 질문이 아직 없는 주제 선언*이라 어떤 FAQ와도 임베딩 매칭이 안 돼 `max_embed_sim < ABS_EMBED_FLOOR(0.60)` → 하드 거절.

### 가드레일 강도 진화 (왜 "되돌리기"가 답이 아닌가)

| 단계 | 커밋 | 거절 조건 | 성격 |
|------|------|-----------|------|
| 최초 | `4cdaf0b` | `top_score < 0.25` | 느슨(recall 우선). 정규화 점수라 거의 통과 |
| 소셜 완화 | `4d1fb5b` | `is_social_chitchat` | 거절 감소 방향 |
| 절대게이트 | `c5e2d79` | `max_embed_sim < 0.60` **OR** `top_score < 0.25` | 엄격(precision 우선). 강도 급상승 지점 |

`c5e2d79`의 절대 임베딩 게이트(0.60)는 *거짓 전제·범위 밖 환각*을 막으려 의도적으로 올린 강도다(실측 보정: 진짜 FAQ 최저 0.634 / 거짓전제·off-topic 최고 0.592 → 0.60). 그러나 이 게이트는 "거짓 전제"와 "범위 내 모호 입력(역량 질문·주제 선언)"을 구분하지 못하고 함께 거절한다. **게이트를 낮추면 환각이 재발하므로**, 해법은 게이트를 *앞에서* 우회시키는 의도 분기를 추가하는 것이다.

## 2. 목표 / 비목표

### 목표
- 역량/가이드 문의("뭘 도와줄 수 있어", "어떤 가이드 받을 수 있어") → 카테고리+예시 질문 **전체 리스트업**(RC-A 해결).
- 범위 내 주제 선언("강의 운영 문의하고 싶어요") → 해당 주제 예시 질문으로 좁혀 안내 + 구체 질문 유도(RC-B 해결).
- 임베딩 게이트 로직·임계값을 **한 줄도 바꾸지 않는다**(환각 보호 유지).

### 비목표 (YAGNI)
- 거절 메시지(NO_GUIDE_MSG)에 제안 삽입 — 이번 범위 제외(사용자 선택).
- 첫 인사(SOCIAL_REPLY)에 예시 덧붙이기 — 이번 범위 제외(사용자 선택). 인사말 텍스트 불변.
- 동적 택소노미(런타임에 인덱스에서 추출) — 정적 큐레이션이 품질·단순성 우위. 제외.
- LLM 기반 분류 — 결정적 사전게이트 원칙(LLM 도달 전 차단) 유지. 제외.

## 3. 설계 (접근법: 게이트 앞 의도 분기 + 제안 데이터 모듈)

### 3.1 모듈 구조

| 파일 | 변경 | 책임 |
|------|------|------|
| `generation/suggestions.py` | **신규** | 토픽 택소노미(데이터) + `build_help_reply()` + `build_topic_reply(topic)` + `match_topic(query)` |
| `generation/guardrail.py` | 수정 | `is_help_request(query)` 추가. `is_social_chitchat`에서 역량 패턴(`_SOCIAL_CAPABILITY`) 제거 → 인사/감사/작별 전담 |
| `generation/stream.py` | 수정 | 라우팅 분기 2개 추가. 임베딩 게이트 로직 불변 |

설계 결정: 역량 문의를 social(짧은 인사)에서 떼어내 **help(리치 리스트업)**로 승격. 따라서 "어떤걸 도와주실수 있는데여"(현재 밋밋한 인사)도 리스트업을 받는다.

### 3.2 라우팅 순서 (`stream_response`)

```
1. is_meta_question(q)        → META_REPLY                      (기존)
2. is_help_request(q)         → build_help_reply()              ★신규: 전체 카테고리+예시
3. is_social_chitchat(q)      → SOCIAL_REPLY                    (기존, 역량 제거됨)
4. match_topic(q) → topic ?   → build_topic_reply(topic)        ★신규: 주제별 예시
5. hybrid_search → 게이트(max_embed<0.60 OR top<0.25) → NO_GUIDE_MSG   ★불변
6. LLM 생성
```

- 2번이 3번보다 앞: 역량 문의를 리치 응답으로 가져오기 위함.
- 4번은 게이트 직전: 진짜 질문은 게이트로 흘려보내고 주제 선언만 가로챔.

### 3.3 토픽 택소노미 + 응답 형식 (카테고리 + 예시 질문)

6개 카테고리, 각 1~2개 실제 FAQ 예시:

| 카테고리 | 토픽 키워드(match_topic용) | 예시 질문 |
|----------|----------------------------|-----------|
| 📚 강의 운영 | 강의 운영, 주차학습, 과목 복사, 수업계획서, 콘텐츠 | "지난 학기 과목을 복사하려면?" / "주차학습에 강의를 어떻게 등록하나요?" |
| 📝 과제·평가 | 과제 | "과제 점수가 학생에게 안 보여요" / "과제 일괄 다운로드가 안 돼요" |
| 🧪 퀴즈·시험 | 퀴즈, 시험, 문제은행, 응시 | "퀴즈가 자동으로 제출됐어요" / "시험 후 재응시를 줄 수 있나요?" |
| ✅ 출결 | 출석, 출결, 전자출결 | "출석했는데 결석으로 처리됐어요" / "전자출결은 어떻게 하나요?" |
| 🏅 성적 | 성적, 채점, 평가, 점수 | "재채점 옵션이 안 보여요" / "대면시험 점수를 LMS로 알려줄 수 있나요?" |
| 👥 수강생·알림 | 수강생, 수강신청, 알림, 공지 | "수강신청했는데 학생이 없어요" / "앱 푸시 알림이 안 와요" |

- **`build_help_reply()`**: 위 6개 전체 리스트업(역량 문의 응답). 출력 형식은 사용자 승인 모킹(카테고리 헤더 + 들여쓴 예시).
- **`build_topic_reply(topic)`**: 해당 카테고리 예시만 + "구체적으로 어떤 점이 궁금하신가요?" 유도(주제 선언 응답).
- 단일 출처 원칙: 두 빌더 모두 동일 택소노미 상수에서 렌더 → FAQ 변경 시 한 곳만 수정.

### 3.4 분류 경계 (정밀도 규칙 — 핵심 리스크)

- **`is_help_request(query)`**: 정규식(결정적). 포함 예 — "뭘/어떤 걸/무엇을 도와줄 수 있어"(④), "어떤 **가이드/안내** 받을 수 있어"(②), "가이드 뭐 있어/보여줘/**보고 싶어**"(③), "뭘 물어보면 돼", "어떤 걸 알려줄 수 있어". 기존 `_SOCIAL_CAPABILITY` 패턴을 흡수·확장한다. 트랜스크립트 ②③④ 모두 True가 되어야 한다(테스트로 고정).
- **`match_topic(query) → str | None`**: **보수적 발화**. *토픽 키워드 + 의도표현("문의/질문하고 싶", "관련해서", "대해 궁금")* 이 있고 *구체 질문 신호(`_QUESTION_HINT`: 어떻게/방법/안 돼/오류 등)가 없을 때만* 토픽 반환.
  - ✅ 발화: "강의 운영 관련 문의하고 싶어요", "과제 관련 질문 있어요"
  - ❌ 비발화(→게이트): "출석했는데 결석 처리됐어요"(구체 문제), "과제 점수가 안 보여요"
  - 원칙: **애매하면 발화 안 함** → 게이트로 폴백(현 동작, 더 나빠지지 않음). 진짜 질문을 가로채는 것이 더 위험하므로 under-fire를 선호.
  - 키워드 중복(예: "점수"가 과제·성적 양쪽) 시 택소노미 정의 순서로 first-match.

## 6. 영향·리스크

- 신규 분기는 모두 게이트 *이전*이라 환각 보호에 영향 없음.
- 유일 리스크: `match_topic` 오발화로 진짜 질문 가로채기 → 보수적 규칙 + 테스트로 차단.
- 응답 길이 증가(리스트업)는 역량/주제선언 입력에 한정 — 일반 답변·인사에는 영향 없음.
