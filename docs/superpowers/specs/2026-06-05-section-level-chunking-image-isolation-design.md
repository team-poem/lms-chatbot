# 섹션 단위 청킹과 이미지 격리 설계

작성일: 2026-06-05

## 배경

노션에서 추출한 매뉴얼 페이지 하나에 서로 다른 하위 주제가 한꺼번에 들어 있는 경우가 있다. 예를 들어 "로그인 / 대시보드 유형 선택" 페이지는 한 문서에 "로그인" 섹션과 "대시보드 표시 유형 선택" 섹션을 같이 담고 있고, 이미지 2장은 모두 대시보드 섹션 소속이다. 로그인 섹션에는 이미지가 없다.

사용자가 로그인을 물으면 답변 텍스트는 맞게 나오지만, 같은 페이지에 있던 대시보드 이미지가 함께 붙어 마치 로그인 관련 이미지인 것처럼 보인다.

## 문제의 근본 원인

원인은 두 군데에 있다.

1. 저장 단계. 청커(`ingest/chunk.py`)는 페이지를 `##`(H2) 기준으로, 그것도 2000토큰을 넘을 때만 분할한다. 위 페이지는 `###`(H3)로 섹션을 나눴고 98단어로 짧아, 통째로 한 청크가 된다. 그 결과 두 섹션의 텍스트와 이미지가 한 청크에 섞인다.

2. 조립 단계. `generation/stream.py`는 답변을 만들 때 텍스트 컨텍스트로 청크를 최대 3개까지 끌어오고, 이미지를 그 3개 청크 전부에서 수집한다. 텍스트 재현율을 위해 이웃 청크를 끌어오는 것은 타당하지만, 이미지까지 무차별로 긁어오는 탓에 형제 섹션의 이미지가 새어 든다.

## 목표

- 한 섹션에 대한 질문에는 그 섹션의 이미지만 노출한다. 다른 섹션의 이미지는 절대 붙지 않는다.
- 수치 임계값에 의존하지 않고 구조로 보장한다.

## 비목표

- 검색 랭킹, 임베딩 모델, 임계값(`ABS_EMBED_FLOOR` 등) 변경은 하지 않는다.
- 섹션 격리를 넘어선 일반적인 이미지 적합도 판단은 하지 않는다.
- 출처(sources) 노출 로직은 이번 범위에서 바꾸지 않는다. 섹션 분할로 출처 제목이 더 정밀해지는 이득은 부수적으로 따라온다.

## 설계: 두 겹 구조 격리

### 1. 저장 단계 격리 — 섹션 분할 (`ingest/chunk.py`)

- 헤딩 인식을 H2와 H3로 확장한다. 정규식 `^(#{2,3})\s+(.+)$`. H1(`#`)은 페이지 제목이므로 분할 기준이 아니다.
- 페이지에 분할 대상 헤딩이 2개 이상이면 토큰 수와 무관하게 그 경계로 나눈다. 헤딩이 0~1개면 지금처럼 한 청크로 둔다. 단순한 페이지가 과하게 쪼개지는 것을 막는다.
- 각 섹션이 `_MAX_CHARS`를 넘으면 기존 `_split_long`이 그대로 추가 분할한다.
- 첫 헤딩 앞 본문(preamble)은, 제목 외 실제 내용이나 이미지가 있으면 페이지 제목으로 별도 청크를 만든다. 제목(H1)만 있으면 생략한다.
- `extract_image_refs`는 이미 청크 본문 단위로 이미지를 추출하므로, 섹션이 나뉘면 이미지는 자기 섹션 청크에만 들어간다. 별도 로직이 필요 없다.

### 2. 조립 단계 격리 — 이미지는 매칭된 섹션에서만 (`generation/stream.py`)

- 텍스트 컨텍스트 구성(최대 3개 청크)은 그대로 둔다.
- 이미지는 1위 청크가 속한 섹션에서만 수집한다. 1위 섹션의 길이분할 연속분(같은 섹션)도 포함한다. 다른 섹션 청크가 텍스트 보조로 끌려와도 이미지에는 기여하지 못한다.
- 판정은 섹션 식별자 비교로 한다. 제목 문자열 추측이 아니라 명시적 키로 비교한다.

### 데이터 모델 — 섹션 식별자

- `app_types.Chunk`에 `section_id: str` 필드를 추가한다.
- 값은 `(source, 섹션 인덱스)` 기반의 안정적 해시다. 같은 섹션의 길이분할 연속분은 같은 `section_id`를 공유하고, 다른 섹션은 다른 값을 갖는다.
- `index/vector_store.py`와 `index/bm25.py` 양쪽 인덱스가 `section_id`를 저장하고 복원하도록 한다. 검색 결과 청크에서 `section_id`를 읽을 수 있어야 조립 단계 비교가 가능하다.

## 재인덱싱

- 청커 변경 후 인제스트 파이프라인을 재실행해 chroma와 bm25를 새로 만든다.
- 데이터(raw/assets)는 그대로 두고 인덱스만 다시 생성한다.

## 테스트 (TDD)

청커 단위 테스트:
- H3 섹션 2개(한쪽만 이미지)인 페이지 → 청크 2개로 분리, 이미지가 각 섹션에만 들어가는지 검증.
- 헤딩 0~1개 페이지 → 단일 청크 유지(회귀 방지).
- preamble 처리: 제목만 있으면 생략, 내용이 있으면 별도 청크.
- 같은 섹션의 길이분할 연속분이 같은 `section_id`를 공유하는지 검증.

조립 단계 테스트:
- 1위 청크가 섹션 A이고 컨텍스트에 섹션 B가 섞여도, 노출 이미지가 섹션 A 것만인지 검증.
- 1위 섹션의 연속분 이미지는 포함되는지 검증.

## 검증

- 80문항 QA 하니스를 재실행해 회귀를 확인한다.
- "로그인" 질문에 이미지가 붙지 않고, "대시보드 유형" 질문에는 그 이미지가 붙는지 직접 확인한다.

## 리스크와 완화

- 섹션 분할로 짧은 청크가 늘어 검색 분포가 바뀔 수 있다. 80문항 재검증으로 확인한다.
- 각 섹션 청크 제목에 페이지 제목을 유지해(`페이지제목 — 섹션`) 맥락 손실을 줄인다.

## 영향 범위 (파일)

- `ingest/chunk.py` — 헤딩 분할 규칙, preamble 처리, `section_id` 부여
- `app_types.py` — `Chunk.section_id` 필드
- `index/vector_store.py`, `index/bm25.py` — `section_id` 저장·복원
- `generation/stream.py` — 이미지 수집을 1위 섹션으로 제한
- 테스트 — 청커, 조립 단계
