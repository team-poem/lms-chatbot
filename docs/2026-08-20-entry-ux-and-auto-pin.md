## 1. LMS 매뉴얼 86편을 노션에서 직접 수집

### 배경

첫 화면을 LMS/CMS 매뉴얼 중심으로 바꾸기로 했는데, LMS 매뉴얼 본문이 인덱스에
없었다(TOC 조차 없어 카탈로그에 CMS 만 떴다). 노션 export 를 기다리지 않고
MCP 로 직접 받아오기로 했다.

### 변경

- `sync/mcp_md.py` — MCP 응답(enhanced markdown) → export 형 md 변환기.
  TOC 는 구조(헤딩·링크·볼드)만 남기고, 본문은 텍스트를 최대한 살린다.
  이미지 URL 은 5분에 만료되므로 fetch 직후 즉시 내려받는다
- 수집은 서브에이전트 3개에 27편씩 분할. 본편 86편 + 이미지 399장 확보
- 재인덱싱: 청크 168 → 489. 검색 품질 실측(분리도 0.1606, 직전 0.1623)으로
  회귀 없음을 확인 — [기준선 기록](baselines/2026-08-19-bge-m3-lms-manual.json)

### 밟은 함정 (재발 방지 반영)

- **제목의 `/` 가 경로 구분자로 먹혀** 13편이 중첩 폴더에 쪼개져 저장됐다.
  에러 없이 "성공"으로 보이는 유형이다. 복구 후 변환 스크립트에 파일명 위생
  처리를 넣었다
- 수집 에이전트의 "27/27 성공" 보고와 디스크 실제 파일 수가 달랐다. 이후
  절차는 **디스크 기준 검수**를 명문화했다(notion-sync 스킬 §2)

## 2. 첫 화면 개편 — 고정 질문과 매뉴얼 최상위 네비

### 변경 (PR #26 → #31 → #33 → #34 순으로 수렴)

- 인트로: "학기 초 자주하는 질문(FAQ)" + 고정 질문 3개(🥇🥈🥉).
  4·5번(EverLec·로그인)은 준비될 때까지 숨김 — 핀은 살아 있어 질문을 직접
  입력하면 확정 답변이 나온다(안정화 시험용)
- 🥇 원격·블렌디드·플립러닝: 인덱스에 근거 문서가 없어 **고정 문안**으로
  답한다 — 자료실 다운로드 링크 안내(`tuning.FAQ_TOP_FIXED`). 노션 페이지가
  생기면 이 항목을 지우고 핀으로 옮긴다
- 가이드 네비: 카테고리 18개가 첫 화면을 덮던 것을 [LMS 매뉴얼] [CMS 매뉴얼]
  두 칩으로 접었다(클릭 시 펼침)
- 폴백 문구 교체: "요청하신 내용에 대한 답변을 찾지 못했습니다. …" 2줄 +
  본문 인라인 링크 대신 [Q&A 게시판 ›] 버튼

### 폴백 문구를 바꿀 때 따라와야 하는 것

폴백 문장은 세 곳이 공유한다 — persona 규칙 5·8(LLM 이 그대로 내뱉는 문장),
`qna_fallback_msg`(게이트·검색 폴백), 프론트 감지. 여기에 더해
**`FALLBACK_MARK`**(LLM 폴백 감지 표지)가 문장의 부분 문자열이어야 한다.
표지를 안 바꾸면 감지가 조용히 죽는다.

## 3. 죽은 세션 자동 재시도 (PR #30)

### 증상

첫 화면에서 질문을 고르면 "연결이 끊겨 새로 시작했습니다. 한 번만 다시 물어봐
주세요."가 떴다.

### 원인

부팅이 localStorage 세션을 검증 없이 신뢰한다. 서버가 모르는 세션(재배포·DB
리셋·다른 계보의 옛 세션)을 가진 브라우저는 첫 `/chat` 이 반드시 403 으로
떨어지는데, 기존 처리는 세션을 재발급하고도 재입력을 사용자에게 시켰다.

### 변경

403 이면 세션을 재발급하고 같은 질문을 한 번만 자동 재시도한다. 실패한 턴은
지워서 화면에 흔적이 없다. 재시도까지 403 이면 그때만 문구를 드러낸다.

## 4. CI 레이스 — 옛 커밋이 latest 를 덮어쓴다 (PR #27)

PR 두 개를 연달아 병합하면 Docker 빌드 둘이 병렬로 돌고, 옛 커밋 빌드가 늦게
끝나면 `latest` 태그를 도로 덮어쓴다. 실측: #26 이미지(05:45:19) 푸시 뒤 #25
이미지(05:45:41)가 `latest` 를 덮어 배포가 옛 코드로 돌아갔다.

`concurrency` 그룹으로 빌드를 직렬화했다. `cancel-in-progress` 는 켜지 않는다 —
돌던 빌드를 죽이면 그 커밋의 sha 태그가 남지 않는다.

## 5. 라이브 전수 시험 101편 → 자동 핀 (PR #35)

### 시험

카탈로그의 문서 질문 101편을 라이브 `/chat` 에 전부 태웠다.
결과: **96 OK / 폴백 4 / 빈 답변 1**, OK 중앙값 1.4초(최대 43초).

### 원인 셋과 수정 셋

| 증상 | 원인 | 수정 |
|---|---|---|
| 폴백 4편 | '웹링크' 같은 짧은 제목은 검색이 자기 문서를 못 찾는다 | **카탈로그 전 문서 자동 핀** — 기동 시 라벨→문서 원문 SSE 맵을 만들어 O(1) 직출력 |
| 핀·노드 누락 20편 | 같은 노션 제목이 소스마다 다른 파일명으로 떨어진다(`퀴즈/설문`·`퀴즈-설문`·`퀴즈 설문`) | `_norm` 이 `/`·`-`·`.`·`?`·`\` 표기 변형을 한 키로 접는다 |
| 빈 답변 1편 | LLM 이 실패하면 빈 말풍선이 그대로 나갔다 | 빈 답변 → QnA 폴백 가드 |

수정 후: 핀 104개(카탈로그 101 + TOP 3) 누락 0, 문제 문서 실호출 전부
score 1.0 · 0.04초 · Gemini 비용 0. 노드 레지스트리 175 → 182(누락 복원).

### 유지보수 관점

자동 핀은 기동 때마다 카탈로그에서 새로 도출된다 — 카탈로그가 바뀌어도 손댈
것이 없다. 손으로 관리하는 것은 `tuning.py` 의 `FAQ_TOP_PINS` 2건과
`FAQ_TOP_FIXED` 1건뿐이다. 도출이 빗나가면 기동 로그에
`카탈로그 핀 대상 없음: …` 이 찍힌다.

## 6. 갱신 절차를 스킬로 (PR #36)

"노션 수집·재인덱싱은 누가 하나"의 답을 저장소에 굳혔다.
`.claude/skills/notion-sync/SKILL.md` 가 트리거("노션 갱신해줘")부터 rsync
핸드오프까지 6단계를 정의한다. 세션 스크래치패드에 있던 변환 스크립트는
`scripts/mcp_ingest_doc.py` 로 승격했고, `scripts/sync_manifest.py` 로 장부
기준선 210편을 저장했다 — 다음 갱신부터 신규·삭제 즉시 판별, 내용 해시로
실변경만 재인덱싱한다.

갱신 가능 범위는 제한이 있다. **현재 MCP 연결로는 LMS 매뉴얼 트리만 접근
가능하다.** FAQ DATABASE 와 CMS 매뉴얼은 옛 계보(404)라, 그쪽이 바뀌면 노션
export 를 받거나 페이지를 연결된 워크스페이스로 공유받아야 한다.
